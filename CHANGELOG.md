# История изменений Luma Music

Сравнение ведётся с предыдущим выпущенным вариантом. Разработка и планы отделены
от выпущенных изменений. Новые возможности не считаются проверенными на аккаунте
только по результатам сборки.

## 1.0.0-dev.1 — подготовка 1.0, после 0.5.0

### Добавлено

- Material Design 3 на нативных Views: темы, кнопки, нижняя навигация и динамический акцент Android 12+.
- Экран «Загрузки»: список скачанного, воспроизведение с диска, удаление, качество 128/192/320,
  Wi-Fi без тарификации по умолчанию и лимит места от 256 МБ до 16 ГБ.
- Rust-загрузчик доступных MP3 Яндекс Музыки: один активный файл, буфер 32 КиБ, приватная
  папка аккаунта, SHA-256, проверка полного размера и публикация готового файла через переименование.
- Фоновая загрузка с уведомлением и отменой. Скачанные треки проверяются перед воспроизведением;
  сломанный файл не подменяется сетевым потоком без сообщения.
- Отдельный Spotify OAuth PKCE, одноразовый state, зашифрованные токены и обновление сессии.
- Просмотр плейлистов и избранного Spotify постранично; открытие выбранного в Spotify.
  Воспроизведение Яндекса останавливается перед передачей управления.
- Экран «Что нового» из того же CHANGELOG.md, который используется в репозитории.

### Изменено и исправлено

- Android и desktop имеют номер 1.0.0-dev.1; Android versionCode 19 обновляет 0.5.0 (18).
- Обработчики кнопки «Назад» переведены на AndroidX dispatcher для Android 11+.
- Проверки, публикация подписанных APK и запрос desktop-сборок используют main.
  Создание и удаление служебных веток больше не требуется.
- AGENTS.md убран из репозитория; рабочие предпочтения сохранены локально.

### Проверки и ограничения

- Rust проверяет PKCE по RFC 7636, неверный/устаревший callback, типы Spotify URI,
  квоту, отмену, недокачку, повреждение файла и разделение офлайн-данных аккаунтов.
- Подготовлен Android-сценарий запуска новых экранов и проигрывания настоящего локального MP3
  без аккаунта. Сетевые загрузки каталога и Spotify требуют отдельной проверки на аккаунтах.
- Spotify требует публичный Client ID и зарегистрированный redirect URI
  org.luma.music://spotify-callback. Spotify-аудио не скачивается в Luma.
- Одновременно скачивается один трек. Постоянная очередь и возобновление с места обрыва
  ещё не реализованы; отменённую загрузку нужно запустить заново.
- Офлайн ограничен доступными обычными MP3, один файл до 128 МБ, до 500 треков.
  При выходе из Яндекса его загрузки удаляются. Защищённые форматы не добавлены.
- Дополнительные переводы остаются частичными. Новые Android-экраны ещё не перенесены в desktop.
- Это предварительная сборка для проверки, не стабильный выпуск 1.0.

## 0.5.0 — выпущена

Сравнение с 0.5.0-rc.8.

### Добавлено и изменено

- Release-APK без режима отладки, versionCode 18.
- Стабильный канал OTA по умолчанию для новых установок; сохранённый выбор канала остаётся.
- Очередь API ограничена текущим и последним ожидающим запросом.
- В «О приложении» показан тип установленного выпуска; диагностика дополнена качеством и типом сети.
- Опубликованы APK для четырёх ABI и universal, Windows Portable, Linux и macOS Intel/Apple Silicon.

### Исправлено

- Предварительная SemVer-версия не попадает в стабильный OTA даже при ошибочном флаге GitHub.
- Устаревшие ответы API не меняют новый экран.
- Ограничены формат/длина OAuth-токена и хосты перенаправлений авторизованных запросов.

### Обновление и проверки

- Прежние org.luma.music и сертификат: обновление поверх RC8 без удаления данных.
- 62 Rust/JVM/Python-теста, Lint, интеграция обновления на Android 11/13 с 2 ГБ RAM.
- Проверены подписи, SHA-256, 16-КБ упаковка; опубликованный Linux-бинарник запускает окно.

### Известные ограничения

- 33 дополнительных перевода частичные; desktop без полного паритета Android.
- Windows 7/8/8.1 экспериментальны, macOS без Developer ID/notarization.
- Автотесты не подтверждают вход и стриминг на настоящем аккаунте.
