# Постоянная подпись и обновления поверх

Android допускает обновление поверх только для того же applicationId и
совместимого сертификата подписи. VersionCode также должен увеличиваться.

Прежние GitHub APK подписывались временным debug-ключом runner. Если его нет
в сохранённом keystore, восстановить закрытый ключ из APK нельзя. Новый ключ
не обновит такую установку: нужна однократная установка с новым ключом.
Перед удалением старой версии учитывайте потерю её локальных данных.

## Если сохранился исходный keystore

Используйте именно его. Не создавайте другой ключ в надежде обновить старую версию.
Для APK из этого чата keystore может сохраниться в облачной машине; для APK из
GitHub нужен ключ соответствующего runner. Автоматически это не доказано.

## Новый постоянный ключ

Создайте его на доверенном компьютере вне checkout. keytool запросит пароль:

```sh
umask 077
keytool -genkeypair -keystore /secure/path/luma-signing.p12 -alias luma -keyalg RSA -keysize 3072 -validity 10000 -dname "CN=Luma Music"
```

Храните резервную копию и пароли вне Git. Установочные выпуски подписываются
локально с помощью `scripts/sign-local-apks.py`, затем CI проверяет готовые файлы
по публичному отпечатку `.github/family-certificate.sha256`. Четыре GitHub Secrets
для этого маршрута не нужны. Не создавайте новый ключ для уже установленных APK.

`build-android.sh` по умолчанию создаёт неподписанный release-APK без режима
отладки. Для локальной разработки можно задать `LUMA_ANDROID_BUILD_TYPE=debug`;
такая сборка не предназначена для стабильного распространения.

При локальном подписании непосредственно Gradle поддерживаются переменные
LUMA_KEYSTORE_PATH, LUMA_KEYSTORE_PASSWORD, LUMA_KEY_ALIAS, LUMA_KEY_PASSWORD.
Не передавайте ключи и пароли в чат, репозиторий или публичные логи.

## Вход через Яндекс

Зарегистрируйте своё мобильное OAuth-приложение с доступом к музыкальному API.
Redirect URI: `yamusicrust://oauth`. В Actions Variables задайте не секретный
`LUMA_YANDEX_CLIENT_ID`. Тогда кнопка «Войти через Яндекс» сразу откроет
настоящую страницу Яндекса. Для тестирования Client ID можно указать на устройстве
в настройках аккаунта. Клиентский секрет не встроен. Основной вход использует публичный Client ID сценария YAYMA; свой ID нужен дополнительному браузерному методу.
Доступные способы входа, в том числе выбор аккаунта, определяет сам Яндекс.

Для каждого нового выпуска повышайте и versionCode, и versionName.
