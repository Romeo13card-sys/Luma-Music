# Luma Music 2.0 — исходный аудит

Дата аудита: 2026-11-21  
База: `main` на `f0a165f5c3303dea8a8ca90441fe22f3ff086610`  
Рабочая ветка: `v2.0-development`

## Сводка

Luma уже имеет работающую основу: Rust-ядро, Android-клиент на Kotlin/Views, JNI, локальное хранилище, отдельный Desktop-клиент на Rust/egui, GitHub OTA, офлайн-загрузки и тексты. Полный rewrite не нужен: он повысит риск поломать OAuth, подпись, локальную базу и аудиосессию.

Главный долг проекта — монолитный UI, несогласованная документация и OTA, которая до этой ветки не сохраняла прогресс скачивания. Версия 2.0 должна улучшить структуру и пользовательский опыт, а не заменить проверенные механизмы ради переписывания.

## Состояние работ после первого прохода

- Базовый аудит, roadmap, постоянное хранилище OTA, HTTP Range-resume и очистка Android Keystore уже попали в `main` через PR #16.
- В PR #17 вынесен следующий этап: общая Android-дизайн-система, обновлённая главная оболочка с четырьмя разделами и mini-player, а также новая Desktop-компоновка.
- Android-Activity остаётся большой: визуальный слой улучшен, но декомпозиция всех экранов на отдельные контроллеры ещё не завершена.
- Плеер, тексты, очереди, библиотека, загрузки и настройки используют общие стили, однако их сценарии ещё требуют отдельного прохода визуального QA.
- PR #17 оставлен Draft. Его mergeable-статус не является доказательством успешной сборки.

## Что уже исправляется в v2.0-development

- OTA использует постоянную папку приложения вместо временного кэша.
- Частичная загрузка привязана к тегу, ID GitHub asset, имени, размеру и SHA-256; несовпадающий asset не продолжает чужой `.part`.
- При поддержке сервером используется `Range: bytes=<offset>-`; перед добавлением байтов проверяется `Content-Range`. Если сервер не поддерживает Range, загрузка безопасно начинается заново.
- Ошибки сети и отмена не удаляют неполный APK. Повторная попытка может продолжить загрузку.
- Перед публикацией готового APK Rust проверяет полный размер и SHA-256.
- В настройках появляется возможность установить сохранённый APK после перезапуска; его SHA-256 и сертификат проверяются повторно.
- Очистка TokenStore удаляет также Android Keystore alias.

## Аудит качества кода

«ИИ-код» невозможно надёжно определить по стилю или отдельным именам: авторство фрагмента не является техническим дефектом. Поэтому очистка проводится по проверяемым критериям:

1. Удаление мёртвого кода, неиспользуемых ресурсов и зависимостей после подтверждения отсутствия ссылок.
2. Замена дублирующих реализаций общими типизированными компонентами и сервисами.
3. Удаление фиктивных обработчиков, демонстрационных заглушек из production-flow, повторяющихся комментариев и устаревших инструкций.
4. Разделение UI, состояния, сетевого слоя и хранилища.
5. Явная обработка ошибок, ограниченные очереди, отмена задач и безопасное восстановление после process death.
6. Тесты на пользовательские сценарии и граничные условия вместо проверки только факта компиляции.

В первичном просмотре ключевых Rust/Kotlin файлов не обнаружены явные `TODO`, `FIXME`, `XXX`, `HACK`, `todo!` или `unimplemented!` маркеры. Это не заменяет полный анализ всех 676 файлов, зависимостей и сгенерированных ресурсов.

## Ограничения проверки

Аудит выполнен по исходникам и метаданным GitHub. В этой сессии ещё не выполнены локальная сборка всех ABI, Android Emulator, Desktop сборки для Windows/Linux/macOS и тестирование реального аккаунта Яндекса/Spotify. Нельзя объявлять корректными OAuth, аудиопоток, уведомления, process-death recovery и системную установку APK, пока соответствующие сценарии не пройдены на эмуляторе/устройстве.

## Инварианты совместимости

- Android applicationId остаётся `org.luma.music`.
- Постоянный сертификат подписи не меняется.
- Существующая база Rust/SQLite, аккаунты, настройки, история и офлайн-файлы мигрируют без потери.
- Старые форматы очередей и офлайн-библиотеки читаются до завершения миграции.
- APK проверяется по package ID, повышению versionCode, minSdk, сертификату и SHA-256.
- GPL-3.0 и upstream notices YAYMA сохраняются.
