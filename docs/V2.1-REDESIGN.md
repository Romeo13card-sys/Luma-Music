# Luma Music 2.1.0 — UI redesign

Status: design and implementation plan  
Target branch: `main` only  
Baseline: stable `v2.0.0`  
Version target: Android `versionCode 27`, `versionName 2.1.0` (increment only when implementation is ready)

## Why this release exists

The 2.0 work improved code organization and introduced a shared visual foundation, but the shipped interface still feels close to the previous layout: a conventional vertical screen, generic cards, a standard bottom navigation bar, and a compact player attached to the bottom. 2.1 must deliver a clearly visible product-level redesign, not just refactoring or token changes.

## Visual direction: Luma Flow

- Distinctive music-first interface with strong album-art presence and clear visual hierarchy.
- Dark graphite as the default canvas, true OLED black, and a carefully tuned light theme.
- Keep the Luma warm-yellow accent as the identity color. Use artwork-derived secondary accents only where stable and contrast-safe.
- Use fewer, more intentional surfaces; avoid stacking generic rounded cards around every control.
- Large editorial track/section typography, compact metadata, consistent spacing and iconography.
- Motion is purposeful and short. Respect Reduce Motion / Reduce Effects and low-memory device policy.
- No expensive blur/glass effects, no animated backgrounds, and no continuous artwork color extraction.

## Android redesign

### Main shell
- Replace the generic header + standard bottom navigation composition with a branded, compact top bar and a custom navigation treatment that visually belongs to Luma.
- Make the current playback state feel integrated into navigation, not like a separate generic card.
- Preserve four clear destinations: Home, Search, Library, Settings.
- Add clear selected, pressed, disabled, loading, and offline states.
- Preserve system insets, large font scaling, TalkBack labels, minimum 48dp touch targets, and Android 11 compatibility.

### Home
- Lead with a personalized greeting / time-aware headline and a visually dominant listening destination.
- Give My Wave a distinctive hero treatment with an obvious play action and a secondary configure action.
- Surface recently played / continue listening and personal collection with stronger artwork-led layouts.
- Avoid redundant explanatory paragraphs and repeated section labels.
- Empty, demo, offline, and signed-out states must be intentionally designed.

### Search and catalog
- Make search the primary interaction, with a clear query field, recent searches, and category/filter affordances.
- Distinguish track, album, artist, and playlist result layouts while keeping row actions predictable.
- Provide polished loading, no-results, network-error, and retry states.

### Library
- Use clear visual groupings for liked tracks, playlists, downloads, history, and local files.
- Make collection navigation and empty states discoverable.
- Preserve existing library data and playback/queue behavior.

### Full player
- Treat the player as a dedicated immersive surface: large artwork, track identity, clear timeline, and prominent playback controls.
- Keep queue, lyrics, like, download, shuffle, repeat, and sleep timer accessible without crowding the primary controls.
- Adapt to short screens and landscape; avoid clipping at large font sizes.
- Preserve playback service, media session, audio focus, and queue semantics.

### Settings
- Present settings as a well-organized index with clear categories and concise descriptions.
- Keep account, appearance, audio, storage/offline, player, OTA, and about settings easy to find.
- Make update status and downloaded APK state explicit without interruptive or misleading success states.

## Desktop redesign

- Build a consistent desktop frame: compact left navigation, a real top search/context area, responsive central content, and a persistent playback dock.
- Give album/playlist/artist pages a coherent hierarchy and artwork-led identity.
- Improve empty/loading/error states and keyboard focus.
- Make the player dock readable at narrow window sizes and support keyboard shortcuts.
- Keep desktop behavior connected to the existing Rust core; do not duplicate music business logic in UI.

## Engineering constraints

- Keep the existing package ID `org.luma.music`, Rust core APIs, database formats, OAuth flows, Android Keystore storage, offline files, and queue semantics compatible.
- Do not change the permanent signing certificate or release channel behavior.
- Do not change the OTA trust checks: release identity, compatible ABI, package ID, version, SHA-256, and signing certificate must still be verified before installation.
- Do not rewrite the app wholesale. Prefer replacing presentation components while retaining tested callbacks and state ownership.
- Do not modify the vendored `vendor/yayma` snapshot unless a separately reviewed upstream patch is required.
- Keep all work on `main`; do not create release or feature branches.

## Definition of Done

- Android home, shell, search, library, full player, and settings have visibly distinct 2.1 layouts.
- Desktop shell, main screens, and playback dock share the new visual language.
- No fake controls or decorative elements that imply unsupported behavior.
- Existing playback, OAuth, library, offline, and OTA flows remain functional.
- Android unit tests, instrumentation smoke tests, lint, Rust fmt/tests, and Desktop CI pass.
- Test on Android API 30 and a current API level; include a constrained-memory device profile.
- Test desktop CI on Linux, Windows, and macOS.
- Update README and CHANGELOG to accurately identify 2.0.0 as the latest stable release until 2.1.0 is actually published.
- Bump version metadata and publish 2.1.0 only after the new UI is implemented and QA is complete.
