# YAYMA → Luma: адаптация до 1.2

Основа: https://github.com/DarkPlayOff/YAYMA, commit
`7b502c0c1e143c7847efb69773abb504abd61b20`, лицензия GPL-3.0.
Полный неизменённый снимок 317 отслеживаемых файлов находится в vendor/yayma.
Он не собирается как второе приложение и сам по себе не включает функции в APK.
Luma и её адаптации публикуются с GPL-3.0, NOTICE и полными исходниками.

## Что уже подключено

| Область | Реализация RC3 |
| --- | --- |
| Переходы очереди | Выбор следующего/предыдущего доступного трека и shuffle теперь в Rust; Android исполняет команду воспроизведения |
| Настройки и очередь | SQLite в Rust, параметры SQL, транзакции и ограничение размера; модель Rust-владения данными как в YAYMA, собственный Android-адаптер Luma |
| Миграция RC2 | Импорт существующих SharedPreferences без перезаписи новых значений; старые файлы очереди удаляются только после успешного импорта; пустая очередь сохраняется как явное состояние |
| Настройки в UI | Небольшой общий снимок значений; записи уходят на один фоновый поток; нет запросов SQLite при отрисовке |
| OAuth-токен | Android Keystore/AES-GCM; не переносится в SQLite обычным текстом |
| OTA | Существующий Rust-транспорт Luma, SemVer, ABI, размер, SHA-256 и совместимость сертификата; источник остаётся Luma-Music |
| Тексты | Неизменённый GPL-парсер LRC/Enhanced LRC YAYMA; запрос LrcLib и обычное окно текста через новый ограниченный Rust-адаптер |
| Информация об устройстве | Модель, Android/API, всего ОЗУ, основная ABI; выбранная и фактически применённая тема; без серийных номеров и идентификаторов |

## Что пока не перенесено из YAYMA

- Полный HTTP/API слой yandex-music-rs и DTO YAYMA: текущие каталог, поиск,
  плейлисты и волна Luma продолжают работать через прежний Rust-клиент.
- Аудиодвижок rodio/CPAL, DSP, эквалайзер, бесшовные переходы, prefetch,
  загрузки каталога и управление файлами. Сейчас воспроизводит MediaPlayer Android.
- Страницы исполнителей/альбомов, редактирование плейлистов, полная библиотека
  и история YAYMA. Наличие этих исходников в vendor не означает работу в Luma.
- TTML, BetterLyrics/YouLyPlus и караоке-подсветка. Парсер сохраняет тайминги,
  но окно RC3 показывает обычный текст.
- Flutter UI: сохранён ранее выбранный нативный интерфейс Kotlin.
- Desktop-only интеграции (Discord, Windows taskbar, tray/hotkeys) не нужны Android.

Это начало интеграции, не завершённая замена всей базы YAYMA. Версия не должна
описывать перечисленные неподключённые возможности как готовые.

## Проверки

Rust-тесты покрывают сохранение между соединениями, повторный импорт, отказ от
сохранения токенов/неизвестных настроек, атомарный отказ невалидного patch,
защиту от понижения версии базы, очистку без восстановления старой очереди,
LRC/Enhanced LRC и обычный/инструментальный текст.
Все четыре ABI надо пересобирать после изменений Rust. Отдельно нужны проверки
миграции и повторного запуска на телефоне, авторизации и настоящего ответа LrcLib.
Системные панели по-прежнему настраиваются после setContentView (исправление #1).

## RC4: авторизация и оформление

Подключён сценарий оконного входа YAYMA: passport.yandex.ru → OAuth → проверка
музыкального аккаунта → Keystore. Нативный WebView — только Android-мост;
публичный client ID и правила URL/state/срока сессии находятся в Rust auth.rs.
Код адаптирован с дополнительными проверками; upstream snapshot не изменён.
Секрет device-flow клиента YAYMA не используется, метод по коду устройства
не заявляется реализованным. Доступ на реальном аккаунте ещё требует проверки.
По запросу пользователя жидкое стекло заменено обычными сплошными темами.

## 1.2: мобильная навигация, очередь, реакции и подборки

Изучены mobile player / mini player, TrackContextActions, QueuePanel и панели
настройки волны upstream. Подход адаптирован к Kotlin Views / Material 3:
компактный плеер, свайпы, отдельная очередь и общее меню трека, 13 одиночных подборок.
Flutter не подключён, vendor/yayma остался неизменным.

Собственные Rust-модули catalog.rs, wave.rs и queue.rs обслуживают страницы
избранного/дизлайков, явные подтверждённые изменения, формат ссылок, сессии и
feedback волны, редактирование очереди с сохранением текущего слота.
Схема rotor/session/new, /tracks и /feedback сверена с используемым YAYMA
протоколом yandex-music 0.7.0; crate не добавлен как вторая HTTP-зависимость.
Предыдущий endpoint личной волны сохранён как резервный. Это не перенос всех DTO.

Неизвестное состояние реакции остаётся неизвестным; локальный аккаунтный кэш
(5000 ID на раздел, TTL60с, до256 подтверждённых изменений) не хранит OAuth-токен.
Сеть выполняется вне блокировки; эпохи не дают позднему GET заменить свежую отметку.
Метаданные загружаются ограниченной страницей. Очередь до200 треков хранит альбом,
но отбрасывает feedback session и expiring URL при сохранении.

Интеграционные проверки используют локальное аудио/изображения: реальные MediaPlayer,
перемотку и паузу, перестановку/удаление очереди, меню с устаревшей ревизией,
свайп мини-плеера и сохранение выбора волны. Сетевые мутации настоящего аккаунта
не выполняются тестами. DSP, Flutter, полный каталог и desktop-паритет остаются
неподключёнными возможностями, даже при наличии исходников в vendor.
