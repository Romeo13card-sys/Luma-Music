# Luma Music 2.0 — план разработки

Рабочая ветка: `v2.0-development`  
Базовая версия: текущий `main` (versionCode 24 / versionName 1.3.1).  
Целевой выпуск: `2.0.0` с повышенным versionCode; точный номер закрепляется перед RC.

## Направление продукта

Luma 2.0 — полноценный музыкальный клиент с единым визуальным языком на Android и Desktop. Существующий Rust core остаётся источником музыкальной логики, каталога, очередей, хранилища, обновлений и правил безопасности. UI не должен повторно реализовывать бизнес-логику.

### Визуальная система

- Тёмная графитовая основа по умолчанию, OLED-black и светлая тема.
- Фирменный Luma-жёлтый акцент; динамический вторичный цвет может браться из обложки, но не пересчитывается на каждом кадре.
- Крупная типографика для названий и текущего трека, компактная типографика для метаданных.
- Большие обложки, спокойные непрозрачные поверхности, чёткая иерархия и единые интервалы.
- Никаких тяжёлых фоновых blur/glass-слоёв; движение только там, где оно помогает понять действие.
- Контраст, доступные hit-targets, TalkBack/клавиатурная навигация и масштабирование текста — часть Definition of Done.

### Android

Новая оболочка с четырьмя постоянными разделами: Волна/Главная, Поиск, Коллекция и Настройки. Мини-плеер остаётся доступен поверх навигации. Полный плеер — отдельный экран с обложкой, прогрессом, очередью и быстрыми действиями.

Перерисовать все пользовательские области в общей дизайн-системе:
- Главная и «Моя волна».
- Поиск треков, альбомов, исполнителей и плейлистов; страницы деталей.
- Коллекция, лайки, плейлисты, история и локальная статистика.
- Полноэкранный плеер, очередь, тексты и локальные файлы.
- Офлайн-загрузки и очередь загрузок.
- Настройки, аккаунты, Spotify, OTA и «О приложении».

Activity не должна содержать разметку всех страниц и сетевую бизнес-логику. Экран принимает модель состояния и события; операции идут через сервис/repository слой.

### Desktop

Общая визуальная система с desktop-адаптацией:
- Боковая навигация с поиском и библиотекой.
- Центральная адаптивная область каталога и деталей.
- Постоянная панель текущего трека, очереди и управления.
- Настоящие пустые состояния, ошибки/повтор, прогресс и отмена.
- Горячие клавиши, клавиатурная фокусировка и масштабирование окна.

### Платформенная граница

Android и Desktop — целевые полнофункциональные клиенты 2.0. iOS-папка в текущем репозитории не содержит эквивалентного клиентского набора функций; её нельзя рекламировать как готовую платформу без отдельного нативного клиента, Rust bridge и тестирования.

## OTA 2.0

Обновление должно переживать перезапуск приложения и потерю процесса:

1. Проверить публичный GitHub Releases, выбранный канал и SemVer.
2. Выбрать один совместимый APK для ABI устройства.
3. Сохранить метаданные конкретного asset и частичный файл в `filesDir/updates`.
4. При повторе проверить идентичность asset и продолжить HTTP Range только после проверки `Content-Range`.
5. Безопасно перезапустить загрузку, если сервер игнорирует Range или partial не соответствует asset.
6. Проверить размер и SHA-256; только потом атомарно переименовать `update.part` в `update.apk`.
7. Перед каждой установкой повторно проверить package ID, versionCode, minSdk, сертификат и SHA-256.
8. Отобразить сохранённый APK после перезапуска; установка всегда требует действия пользователя.
9. Удаление обновления очищает APK, partial и metadata, не трогая аккаунт, настройки и offline library.

Загрузка из настроек и системного picker должны использовать одну проверку APK, но локально выбранный файл нельзя ошибочно принимать за GitHub-файл по устаревшей metadata.

## Архитектура и качество

- Rust core: типизированные DTO на границе dispatch; отдельные модули каталога, auth, playback/queue, storage, lyrics, downloads и OTA.
- Android: тонкий Activity host, отдельные screen/controller классы, единый DesignSystem, lifecycle-aware операции.
- Desktop: разделить eframe presentation, app state, background jobs и player state.
- Удалить неиспользуемые ресурсы/зависимости только после поиска ссылок и контрольной сборки.
- Оставить upstream YAYMA вендорный снимок неизменённым; вести отдельные патчи адаптаций и соблюдать GPL-3.0.
- Вся пользовательская строка должна иметь ключ локализации; переводы проверяются по ключам, а неполный перевод не должен маскироваться как полный.
