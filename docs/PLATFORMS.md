# Desktop RC7 и поддерживаемые платформы

Это кандидаты для проверки на устройствах, а не подтверждение всех версий ОС.
Архивы публикуются в GitHub Release вместе с SHA-256 после успешных сборок/проверок.

| Архив | Сборка и условия |
| --- | --- |
| Windows-10-11-x64-Portable | Rust 1.90, обычный x64 MSVC target, статический CRT. Запуск `--self-check` на build-host Windows |
| Windows-7-8-8.1-x64-Portable-experimental | Отдельный `x86_64-win7-windows-msvc`, nightly-2025-09-18, build-std, статический CRT, subsystem 6.01 |
| Windows-7-8-8.1-x86-Portable-experimental | То же для `i686-win7-windows-msvc`, 32 бита |
| Linux-x64 | Ubuntu 22.04, glibc 2.35+, ALSA, X11/Wayland и OpenGL. Графический smoke-test через Xvfb/Mesa |
| macOS-x64 / macOS-arm64 | `.app`, deployment target macOS 11.0, ad-hoc-подпись. Developer ID/notarization отсутствуют |

Для старых Windows нужны Windows 7 SP1/8/8.1 с обновлениями системы и драйвером
OpenGL. Стандартный Rust target теперь требует Windows 10; переименование
обычного EXE не даёт Windows 7-совместимость. Использован специальный
[Tier 3 target Rust](https://doc.rust-lang.org/rustc/platform-support/win7-windows-msvc.html).
CI проверяет подсистему PE и известные несовместимые статические/отложенные
импорты, включая ProcessPrng/WaitOnAddress/GetDpiForWindow. Это неполный аудит
API и **не замена запуску на настоящих Windows 7, 8 и 8.1**. Legacy-архивы
помечены experimental до такой проверки; ошибки сборки/аудита блокируют их публикацию.
Windows 10/11 и macOS тоже требуют пользовательской проверки графики и аудио.

## Windows Portable

Скачайте ZIP для своей системы, распакуйте целиком в отдельную папку и запустите
`luma-desktop.exe`. Установка и права администратора не требуются; папку можно
перенести на флешку. Статический CRT позволяет обойтись без отдельной установки
Visual C++ Redistributable. В архиве есть `START-HERE.txt`, лицензии и сведения
о сборке; рядом опубликована SHA-256. Нужны системные драйверы графики/звука.

Текущий desktop хранит OAuth-токен только в памяти сеанса. Временные аудиофайлы
создаются в системном временном каталоге и удаляются при нормальном закрытии;
аварийное завершение может оставить их там. Перенос папки не переносит аккаунт.
Для обновления закройте приложение и распакуйте новый архив в отдельную папку.
Portable не означает автоматическое desktop OTA — оно пока не реализовано.

## Что умеет desktop

Общий Rust API/парсер аудио с Android. Ручной OAuth-токен, проверка аккаунта,
поиск, избранное, получение партии волны. Токен остаётся только в памяти сеанса.
Очередь сохраняется при новом поиске, есть предыдущий/следующий трек, автопереход,
повтор, пауза, стоп, громкость, перемотка при известной длительности, качество
128/192/320, светлая/тёмная тема и перезапуск аудиовыхода после смены устройства.

Аудио сначала загружается во временный файл: максимум 100 МиБ, буфер 32 КиБ,
проверка Content-Length при наличии. Во время загрузки видны прогресс в МиБ и
кнопка отмены; HTTPS-аудиотранспорт принимает только доверенные редиректы Яндекса.
Тайм-аут загрузки 60 с. Отмена не прерывает немедленно блокирующий connect/read:
она проверяется между порциями данных и до воспроизведения. Пока старый запрос
не завершился, новая задача не запускается — не накапливаются сетевые потоки.
Декодер создаётся в фоне. OutputStream переиспользуется, а остановленная очередь
Sink заменяется без ожидания завершения старого трека в GUI. Ответы устаревших
или отменённых задач не запускают воспроизведение и не подтверждают вход.

Не реализованы оконный OAuth desktop, сохранение токена в хранилище ОС, полная
непрерывная волна/feedback, библиотека офлайн и автоматический desktop OTA.
Кнопка Releases открывает страницу скачивания вручную. Реальный расход RAM,
доступность подписки, аудиоустройства и воспроизведение на аккаунте не измерены
автотестами. Нет гарантии всех кодеков и защищённых потоков.

## Сборка

`cargo test --locked -p yamusic-core -p luma-desktop`
`cargo build --release --locked -p luma-desktop`

Linux development packages: libasound2-dev, libxkbcommon-dev, libwayland-dev,
libgl1-mesa-dev. Для запуска нужны ALSA/OpenGL/графическая сессия.
Windows: MSVC Build Tools/SDK. Для legacy — rust-src и build-std как в workflow.
Apple: Xcode Command Line Tools, macOS SDK. `scripts/package-desktop.py`
проверяет версию/target исполняемого файла, создаёт архив с лицензией, исходным
commit и SHA-256; macOS получает `.app` и ad-hoc-подпись.

Workflow `Desktop release` запускается только owner-push ветки `publish-desktop/**/v...`
с теми же исходниками приложения/зависимостей/лицензий, что опубликованный тег.
Исправления build recipe допускаются отдельно и записываются в build-info.json. Он создаёт обычные и legacy
архивы в отдельных jobs и прикрепляет их к существующему Release без перезаписи.
Отказ legacy job не скрывает успешно собранные современные платформы.

## iPhone

Исходный preview SwiftUI/AVPlayer + Rust остаётся в `ios/`: ручной токен в RAM,
аккаунт, поиск/избранное/партия волны и выбранный MP3. CI `Luma platform previews`
делает unsigned ARM64 `.app` для iOS-симулятора. Это не IPA для физического iPhone.
Нужны macOS/Xcode, Apple team/сертификат/provisioning для устройства; оконный OAuth,
Keychain и распространение TestFlight пока не подключены. Не проверено на iPhone.
