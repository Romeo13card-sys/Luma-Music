# Luma Music — «Жидкое стекло», тестовая версия 0.2.2

made by Romeo13card

Неофициальный Android-клиент Яндекс Музыки: Rust-ядро, нативный интерфейс Kotlin,
тема «Жидкое стекло»: стеклянные панели, мятные акценты и статические градиенты. Без WebView для интерфейса,
Compose, постоянного размытия и графических библиотек. Приложение не связано с Яндексом.

## Что реализовано

- Авторизация личным OAuth-токеном; хранение AES-GCM / Android Keystore.
- Браузерная OAuth-авторизация для собственного зарегистрированного Client ID;
  проверка одноразового `state`, срок ответа 10 минут, подтверждение аккаунта через API.
- Поиск треков, плейлисты пользователя, первые 100 избранных треков.
- Фоновое воспроизведение через foreground service, MediaSession, уведомление
  с кнопками, системные медиакнопки и метаданные для экрана блокировки.
- Очередь, следующий/предыдущий трек, перемотка, повтор трека и перемешивание.
- Обработка аудиофокуса и отключения наушников.
- Воспроизведение собственных файлов через системный выбор документа, без разрешения
  на доступ ко всей медиатеке и без отправки файлов на сервер.
- Деморежим без аккаунта: интерфейс и короткий локальный синтезированный звук.
  Деморежим не изображает подключение к Яндексу и не содержит чужой музыки.
- Выход очищает токен и останавливает воспроизведение.

## Тестовые APK

В `android/app/build/outputs/apk/debug/`:

- `app-arm64-v8a-debug.apk` — большинство современных телефонов, около 5 МБ.
- `app-x86_64-debug.apk` — x86_64 эмулятор.
- `app-universal-debug.apk` — обе архитектуры, около 8 МБ.

Все APK подписаны отладочным ключом. Это сборки для тестирования, не готовый выпуск.
Для первого знакомства нажмите «Попробовать без аккаунта», затем
«Слушать тестовый звук» или откройте собственный аудиофайл.

## Вход

Нужны свой аккаунт и подписка Яндекс Музыки. API неофициальный:
доступность зависит от сервиса, аккаунта и региона. Проверка настоящего каталога
и подписки требует реального аккаунта; деморежим её не заменяет.

Можно ввести личный OAuth-токен прямо в приложении. Не отправляйте его в чат,
не сохраняйте в Git или CI. Пароль Яндекса приложение не запрашивает.

Для входа через браузер зарегистрируйте своё приложение в Яндекс OAuth,
получите доступ к Яндекс Музыке и зарегистрируйте Redirect URI
`yamusicrust://oauth`. Введите Client ID в диалоге «Войти через браузер».
Чужой Client ID не встроен. Без выданных Яндексом прав эта функция не предоставит
доступ к музыкальному API. OAuth-переход и доступ с реальной учётной записью
должны быть проверены владельцем Client ID.

## Совместимость

Android 11 (`minSdk 30`) — Android 17 (`targetSdk 37`, SDK Platform 37.0).
ARM64 и x86_64, нативные ELF и упаковка с выравниванием 16 КБ.
Отсутствие верхнего ограничения не доказывает работу на всех версиях Android.
AGP 8.13 официально проверен до SDK 36.1 и предупреждает об SDK 37;
предупреждение не подавлено. Полный прогон Android 11–17 необходим перед выпуском.

## Сборка на Linux x86_64

Нужны полный JDK 17/21 (с `javac`), Rust 1.90.0, Android SDK Platform 37.0,
Build Tools 36.0.0 и NDK 27.2.12479018. Gradle Wrapper закрепляет 8.13 и SHA-256.

```sh
rustup target add aarch64-linux-android x86_64-linux-android
cargo test --workspace --locked
export ANDROID_HOME=/path/to/android-sdk
./scripts/build-android.sh
cd android
./gradlew lintDebug
```

Скрипт собирает оптимизированное ядро Rust (`opt-level=z`, LTO, удаление символов)
для обеих ABI и упаковывает APK. Не запускайте только Gradle после изменения Rust:
сначала нужно обновить нативные библиотеки этим скриптом.

## Что ещё требует работы перед выпуском

Это расширенный тестовый клиент, а не полная копия официальной Яндекс Музыки.
Пока отсутствуют «Моя волна», офлайн-загрузка каталога, редактирование плейлистов,
изменение избранного, история синхронизации с сервисом, тексты, эквалайзер,
восстановление очереди после завершения процесса и публикация с выпускным ключом.
Список избранного ограничен 100 треками; поиск показывает первую страницу.
Обложка плеера — лёгкая абстрактная графика, не обложка текущего альбома.

## Проверки

- Rust: 5 тестов — разбор треков, ошибки токена, проверка доменов аудио,
  подпись потока, защита параметров плейлиста от подстановки пути.
- Тесты не обращаются к настоящему аккаунту и не доказывают работу сервиса.
- Практический сценарий: демо → звук → пауза → продолжение → перемотка → фон
  → уведомление → возврат в приложение → очередь → выход.
- Проверить отдельно: токен и браузерный вход, реальный каталог, Bluetooth,
  звонок, отсутствие сети, истечение токена и разные размеры экрана.

Ориентир архитектуры: [PrivateMusicDesktop](https://github.com/decoder-dev/PrivateMusicDesktop).
Его исходники, брендинг и ресурсы не копировались.

## Проверки перед публикацией

Проверяются форматирование Rust, 5 модульных тестов, сборка APK, Android Lint,
подпись и упаковка с выравниванием 16 КБ. Практический тест демоплеера:

```sh
ADB="$ANDROID_HOME/platform-tools/adb" python scripts/smoke-android.py
```

Для него нужен установленный APK, полностью загруженный Android и экран входа
без сохранённого аккаунта. Тест проверяет деморежим, активную MediaSession
и продолжение воспроизведения в фоне. Снимок сохраняется в
`android/app/build/outputs/smoke/`. В текущей облачной среде этот сценарий не прошёл
до выполнения: программный эмулятор не завершил загрузку. Работу реального
аккаунта и совместимость Android 11–17 нужно проверить отдельно.

## Тестовые выпуски

Отправка тега `v*` запускает проверку и сборку, затем публикует APK и SHA-256
в GitHub Releases с отметкой **Pre-release**. Выпуск создаётся только после
успешного завершения сборочного задания. Запуск на push в main оставляет APK
в Artifacts и не создаёт выпуск. GitHub-токен с правом записи используется только
в отдельном задании публикации тега; для сборки используется доступ на чтение.
Тестовый выпуск не является выпуском в Google Play.

## Название проекта и репозитория

Название приложения: **Luma Music**. Рекомендуемое название репозитория:
`luma-music`. Переименование существующего приватного репозитория на GitHub
в этих изменениях не выполняется; GitHub URL остаётся прежним до отдельного
переименования в Settings → General → Repository name. После него нужно
обновить origin и выбранный репозиторий среды. Android applicationId сохранён,
чтобы новая версия могла обновлять существующую установку.

## Исправление Setup Android SDK

В setup-android@v3 значение packages по умолчанию включает удалённый пакет
`tools`. Workflow явно задаёт `packages: platform-tools` и использует
Command-line Tools build 13114758. Нужные SDK/Build Tools/NDK устанавливаются
отдельным следующим шагом. Лицензии принимаются стандартным действием,
но их полные тексты больше не засоряют лог.
