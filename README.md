# Luma Music

made by Romeo13card

Неофициальный Android-клиент Яндекс Музыки: Rust-ядро, нативный Kotlin-интерфейс,
без Flutter и Compose. WebView создаётся только для входа. Кандидат в релиз 0.5.0-rc.7, applicationId `org.luma.music`.

## Совместимость и APK

Минимум Android 11 (API 30). `compileSdk = targetSdk = 36` (Android 16).
Android 17 / SDK 37 больше не используются для сборки. Это не запрет установки
на более новых ОС: `maxSdkVersion` намеренно не задаётся.

Поддерживаются четыре архитектуры:

| APK | Архитектура |
| --- | --- |
| `Luma-Music-0.5.0-rc.7-armeabi-v7a.apk` | ARMv7, 32 бит |
| `Luma-Music-0.5.0-rc.7-arm64-v8a.apk` | ARM64 / aarch64 |
| `Luma-Music-0.5.0-rc.7-x86.apk` | x86 / i386 |
| `Luma-Music-0.5.0-rc.7-x86_64.apk` | x86_64 |
| `Luma-Music-0.5.0-rc.7-universal.apk` | Все четыре ABI |

Локальные сборки без LUMA_KEYSTORE_PATH имеют отладочную подпись; тег-выпуски требуют постоянный ключ в GitHub Secrets. Для телефона выбирайте APK его архитектуры:
универсальный больше по размеру. Нативные ELF и ZIP имеют выравнивание 16 КБ.
Запуск старой сборки на Android 13 подтверждён пользователем; это не заменяет
проверку нового APK и каждой ABI на устройствах.

## Что работает в коде

- Личный OAuth-токен, проверка аккаунта, шифрование Android Keystore / AES-GCM.
- Браузерный OAuth-вход с собственным Client ID и Redirect URI `yamusicrust://oauth`.
  Проверяется одноразовый state. Пароль Яндекса приложение не запрашивает.
- Поиск, плейлисты, первые 100 избранных треков.
- Экспериментальная «Моя волна»: партии, feedback начала/окончания/пропуска,
  продолжение потока. Нужны аккаунт, подписка и доступ к неофициальному API;
  работа волны на реальном аккаунте пока не подтверждена.
- Фоновый плеер, MediaSession, уведомление, перемотка, повтор и перемешивание.
- Сохранение до 200 метаданных очереди и позиции; без токена и URL аудиопотоков.
- Свои файлы через системный выбор документов. Демо со своим тестовым звуком.

## Интерфейс 0.5.0-rc.7

Основной вход RC4 — отдельное нативное окно с официальной страницей Яндекса,
по сценарию YAYMA. Используется тот же публичный OAuth Client ID без client secret.
После входа Яндекс возвращает токен, Rust проверяет origin, state, срок сессии
и формат ответа; музыкальный API проверяется до зашифрованного сохранения.
Пароль и поля страницы приложение не читает; JavaScript-мостов и инъекций нет.
WebView освобождается при закрытии окна. Требуется установленный Android System WebView.
Доступность входа для настоящего аккаунта и права этого клиента надо проверить
на телефоне. Дополнительно сохранены браузер со своим Client ID и ручной токен.

Экран «Настройки» содержит четыре темы, качество звука по типу сети, таймер сна,
уменьшение эффектов, переход к уведомлениям Android, плеер, аккаунт и OTA: вибрацию, повтор,
перемешивание, каналы stable/test, проверку/скачивание обновлений, установку
скачанного APK и публичный источник без GitHub-токена. Подпись автора
`made by Romeo13card` остаётся в разделе информации. Выход требует подтверждения.

Оформление RC4: обычные непрозрачные светлая и тёмная темы, системный выбор
и OLED. Жидкое стекло удалено: нет прозрачных панелей, бликов, фоновой линзы
или RenderEffect-размытия. Ссылки на Telegram и поддержку автора открываются
из информации о приложении через Android.

## Память и производительность

Профиль выбирается один раз на экран Activity. Экономичный режим включается
для low-RAM устройств, ОЗУ до 3 ГиБ или небольшого Java heap:

| Ограничение | Экономичный профиль | Обычный профиль |
| --- | --- | --- |
| Строк на странице | 20 | 40 |
| Обновление плеера на видимом экране | 1 раз/с | 2 раза/с |
| Размытие / прозрачные панели | Нет | Нет |
| Сохранённая очередь | До 200 метаданных | До 200 метаданных |

Страницы заменяют предыдущие View. При смене экрана освобождаются ссылки
на старые панели. В фоне цикл обновления UI прекращается. Шейдер обложки-заглушки создаётся
при изменении размера, не на каждый draw. Приложение не резервирует память
пропорционально ОЗУ: даже профиль с 2 ТиБ получает те же фиксированные пределы.

Эти лимиты проверяются unit-тестами, но конкретный расход RAM на телефоне
не измерялся. Поддержку диапазона устройств от 2 ГБ нельзя подтвердить одной
сборкой: нужны замеры на реальных 32- и 64-битных устройствах.

## Сборка

Linux x86_64, JDK 17/21 с javac, Rust 1.90.0, SDK Platform 36,
Build Tools 36.0.0, NDK 27.2.12479018. Gradle Wrapper 8.13 проверяет SHA-256.

```sh
rustup target add armv7-linux-androideabi aarch64-linux-android i686-linux-android x86_64-linux-android
cargo test -p yamusic-core --locked
python3 -m unittest discover -s scripts -p 'test_*.py'
export ANDROID_HOME=/path/to/android-sdk
./scripts/build-android.sh
cd android
./gradlew testDebugUnitTest lintDebug
cd ..
python3 scripts/package-apks.py
```

Готовые именованные APK и SHA256SUMS.txt: `android/app/build/outputs/distribution/<версия>/`.
Не запускайте только Gradle после изменения Rust: сначала пересоберите JNI скриптом.
`CARGO_TARGET_DIR` поддерживается для повторного использования каталога сборки.

## GitHub Actions и тестовые выпуски

Push в main, pull request и ручной запуск проверяют Rust, Python-упаковку,
JVM-тесты тем и профиля памяти, сборку всех ABI, Lint, подписи и 16-КБ упаковку.
Артефакты `luma-music-apk-<номер>` хранятся 14 дней. Тег `v*` дополнительно создаёт
GitHub Pre-release после успешных проверок. Секреты Яндекс Музыки для CI не нужны.
Дополнительный вариант подписи в CI: тег-релиз останавливается без постоянного ключа: новые случайные debug-ключи
больше не публикуются как совместимые OTA-релизы. Старая GitHub debug-установка
может быть обновлена поверх только её исходным ключом; из APK его не восстановить.

OTA: [как работает загрузка и установка](docs/UPDATES.md).
Обязательная настройка: [подпись, секреты CI и OAuth Client ID](docs/SIGNING.md).
Не реализованы офлайн-загрузки каталога, редактирование плейлистов, эквалайзер,
тексты и публикация в магазине. Автотесты не подтверждают доступ к настоящему
каталогу, Bluetooth, звонки, OAuth-приложение или качество звука на устройстве.

Ориентир архитектуры: [PrivateMusicDesktop](https://github.com/decoder-dev/PrivateMusicDesktop).
Его исходники и ресурсы не копировались.

Новая основа интеграции RC3: [YAYMA](https://github.com/DarkPlayOff/YAYMA), GPL-3.0.
Полный исходный снимок и адаптации сохраняют авторство: см. LICENSE, NOTICE
и [состояние переноса](docs/YAYMA-MIGRATION.md). Снимок не означает, что все функции уже подключены.


## Основной семейный маршрут обновлений

Публичный репозиторий `Romeo13card-sys/Luma-Music` содержит исходники и Releases.
Токен GitHub в приложении не используется. Локальная подпись одним постоянным
ключом вне Git не требует четырёх GitHub Secrets.
[Подпись и публикация](docs/PUBLIC-RELEASES.md).

Свой OAuth Client ID требуется только для дополнительного браузерного метода;
основное окно использует публичный идентификатор клиента YAYMA.
Полный сценарий OAuth и OTA на устройстве пока не проверен.

## Rust-ядро 0.5.0-rc.7

Rust выполняет запросы музыкального API, обработку каталога и волны, выбор
качества потока, нормализацию и ограничение снимков очереди, выбор выпуска/APK,
загрузку обновлений, SHA-256 и правила совместимости подписи и версии. Версии RC
сравниваются по SemVer, включая переход rc.2 → rc.10 → стабильный выпуск.
Kotlin отображает нативный UI и связывает ядро с Android: MediaPlayer/MediaSession,
Keystore, путь к приватной базе, браузер OAuth, сертификаты и системный установщик.
Настройки и очередь сохраняются в SQLite через Rust; старые SharedPreferences
импортируются без перезаписи уже изменённых значений.
Это выбранная архитектура; Kotlin остаётся для интерфейса и интеграции с ОС.
Offline JNI-вызовы не создают HTTP-клиент. Тесты перенесённых правил живут в Rust.

0.4.0 был тегом, но выпуск APK остановился на проверке ключа. Наличие тега
не означает наличие GitHub Release. Новый workflow Publish signed APKs принимает
готовые локально подписанные APK через временную ветку publish-apk/* и проверяет
сертификат по публичному pin, package/version, SHA-256 и упаковку, после чего
создаёт предварительный Release и удаляет транспортную ветку. Закрытый ключ в Git/CI
не попадает; четыре signing-секрета не нужны для этого маршрута.

## RC5: минимализм и платформенные preview

Нейтральные светлая/тёмная/OLED-палитры с жёлтым акцентом, компактная главная
с волной на первом месте, мини-плеер с отдельной паузой, отметка текущего трека
в очереди и переход к его странице, перемотка ±10 секунд. Без фоновых эффектов.

Выбор MP3 принимает отсутствующее поле transport и строковый битрейт. Если
доступный битрейт выше лимита сети, ошибка явно сообщает доступные значения:
лимит не повышается без пользователя. Реальный ответ проблемного аккаунта
пока не получен, поэтому устранение конкретной ошибки нужно проверить на телефоне.

[Windows/Linux/macOS и iPhone: сборки и ограничения](docs/PLATFORMS.md).

## RC6: аудиоссылка и настройки

Исправлена ошибочная проверка ts при формировании подписанной ссылки MP3:
серверная метка не обязана состоять только из десятичных цифр. Буквенные
метки поддерживаются; небезопасные символы URL по-прежнему отклоняются.
Метаданные аудио читаются из XML и JSON с ограничением 256 КиБ; ошибки запроса
качества и метаданных сервера теперь различаются.

Настройки разделены на страницы с локальным поиском: звук/сеть, оформление,
воспроизведение, хранилище, обновления, аккаунт и информация. Добавлены размер
текста, пауза без наушников, остаток таймера сна и 90 минут, текущий тип сети,
повторный запуск трека после смены качества, сведения для поддержки без токенов
и безопасный сброс параметров без удаления очереди, аккаунта или файлов.
Хранение и сброс параметров принадлежат Rust/SQLite; авторизация остаётся в Keystore.
Работа настоящего потока на аккаунте и новые страницы требуют проверки на телефоне.

## RC7: стабилизация и desktop-релиз

Desktop: очередь отделена от результатов поиска, отмена и проверка ответов задач,
ограниченные загрузки с прогрессом, проверка целостности и фоновое декодирование,
переиспользование аудиовыхода, громкость/автопереход/повтор/перемотка и ручной
перезапуск устройства. В Android записи очереди больше не отменяются вместе
с worker плеера при остановке сервиса. Ответы музыкального API ограничены 4 МиБ.

[Desktop Release: платформы и ограничения](docs/PLATFORMS.md). Windows 7/8/8.1 —
отдельный экспериментальный build-std target x86/x64 с PE-аудитом, без обещания
работы на непроверенной системе. Windows 10/11, Linux и macOS получают свои
архивы. Успешная компиляция и --self-check не заменяют проверку графики/аудио.
